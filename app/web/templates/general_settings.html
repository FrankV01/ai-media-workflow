FourthWall

Publishes the job's delivery archive as a digital product: the customer ZIP becomes the downloadable file and the smallest per-variant renderings become preview images. API credentials are read from FOURTHWALL_API_USER / FOURTHWALL_API_PASSWORD in .env — they are never stored in the database.

Products are created hidden unless "Publish on create" is on — the API cannot publish later, so hidden products are published manually from the Fourthwall admin.

$description/$tags come from the Social Media Specialist's marketplace post (falling back to the Art Director's brief); $title is the shoot name; $attribution is the artist attribution above.

PayHip

PayHip cannot be automated: its public API offers no endpoint for creating products or listing files for sale — only sales notifications (IPN/webhooks) are exposed. To sell a delivery archive on PayHip, create the listing manually in the PayHip dashboard and upload the ZIP by hand.

What goes into a delivery

Delivery archives intentionally contain the complete job output — renderings, cutouts, and reports — plus the full creative process record (_delivery/creative_process.md), which includes internal prompts, model settings, and request parameters. Application credentials and environment configuration are not exported; prompts, outputs, and anything you write into them ship verbatim.
